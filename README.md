# iOS 虚拟定位轨迹工具（macOS）

在 Mac 上给 iPhone / iPad 做**虚拟定位**与**轨迹模拟**的桌面工具：在地图上绘制路线、添加途经点、按真实速度沿轨迹驱动手机定位。支持 **iOS 17 ~ iOS 26**（RSD 隧道 + DVT `SimulateLocation`）以及 iOS 16 及更早版本（usbmux + 开发者镜像）。

界面为本机网页应用，用 Chrome / Edge 的应用窗口打开（无地址栏，像原生 App），也可以直接用浏览器访问 `http://127.0.0.1:8787`。地图、轨迹、播放引擎、设备通信全部在本机完成，只有地图瓦片和（可选的）路线规划需要联网。

## 1. 快速开始

```bash
cd ~/Desktop/location

# 首次运行会自动创建虚拟环境并安装依赖（走国内镜像）
./scripts/run.sh
```

启动后会自动打开界面。命令行等价方式：

```bash
./.venv/bin/python main.py                 # 正常启动（自动打开界面）
./.venv/bin/python main.py --mock           # 无设备模拟模式（演示/验收轨迹与播放）
./.venv/bin/python main.py --port 8899 --no-browser
./.venv/bin/python main.py --window browser # 用默认浏览器打开而不是应用窗口
```

## 2. 设备准备（关键）

| 要求 | 说明 |
| --- | --- |
| 数据线连接 | iOS 17+ 建议用 USB；Wi-Fi 连接在传输大文件时容易断 |
| 解锁并「信任」 | 手机弹出「要信任此电脑吗」必须点**信任**并输入锁屏密码 |
| 开启开发者模式 | iOS 16+ 必需。设置 → 隐私与安全性 → **开发者模式** → 打开 → **重启手机** → 重启后确认开启 |
| 挂载开发者镜像 | iOS 17+ 必需（Personalized DDI）。见下方命令 |
| 关闭同类工具 | 爱思助手 / i4Tools 等会与本工具争抢同一条 RSD 连接，**同一时间只能开一个** |

### 挂载开发者镜像

```bash
cd ~/Desktop/location

# 查看是否已挂载（返回 [] 表示没挂）
./.venv/bin/python -m pymobiledevice3 mounter list

# 自动挂载（首次需要联网下载素材，见下方"网络受限时"）
./.venv/bin/python -m pymobiledevice3 mounter auto-mount --udid <你的UDID>
```

也可以直接用 Xcode：连接设备 → Window → Devices and Simulators → 等待 "Preparing device for development" 完成。

> macOS 装有 Xcode 时，系统自带的 `CoreDeviceService` 通常会在设备接入后**自动挂载**本地素材
> （`/Library/Developer/DeveloperDiskImages/iOS_DDI`），此时 `mounter list` 会直接显示已挂载，无需任何操作。

#### 网络受限时：离线挂载（本机实测有效）

`raw.githubusercontent.com` 在国内常被 **SNI 级阻断**（DNS 轮询到 4 个 IP 中只有 `185.199.111.133` 可用，
其余被 RST 或黑洞），而 pymobiledevice3 拉素材时没有重试，因此 `auto-mount` 会直接报
`ConnectionResetError: Connection reset by peer`。解决方式是把素材下载到本地缓存，之后完全离线可挂：

```bash
# 固定可用 IP + 重试 + 校验字节数，并写入 pymobiledevice3 缓存
./tools/ddi_offline_fetch.sh

# 之后即可离线挂载（不会再访问 GitHub）
./.venv/bin/python -m pymobiledevice3 mounter auto-mount --udid <UDID>
```

### 关于 iOS 17+ 的隧道（RSD）

iOS 17 起，虚拟定位服务不再走 usbmux，必须先建立 **RSD 隧道**。本工具有三种方式：

1. **免 root（默认，推荐）**：自动执行 `pymobiledevice3 remote start-tunnel --native --script-mode`，借用 Apple 自带 `remoted` 的隧道。实测在本机可用。
2. **管理员模式**：界面上点「以管理员权限重建隧道」（会弹系统密码框），或直接 `sudo ./scripts/run.sh`。
3. **手动填 RSD**：界面「手动 RSD」按钮，填入 `HOST PORT`（例如从其它工具或 `tunneld` 拿到）。

> `remote tunneld`、`lockdown start-tunnel`、经典 `remote start-tunnel` 都**必须 root**，本工具不会静默提权。

## 3. 界面功能

### 顶部：设备区
- 设备名 / 型号 / iOS 版本 / 连接方式（USB/网络）
- **隧道**状态、**虚拟定位**状态、**开发者模式**状态
- 「刷新设备」「连接设备」「断开」

### 左侧：轨迹设置
- **出行模式**：驾车 / 骑行 / 步行 / 飞行（决定基准速度与是否走真实路网）
- **播放倍速**：0.1x ~ 50x（只影响轨迹推进速度，不影响下发频率）
- **循环播放**：到终点自动回到起点
- **真实感模拟**（校园跑等打卡类 App 测试的关键，可随时开关、播放中也能改）：
  - **定位漂移**：模拟 GPS 误差导致的缓慢游走，半径 0~50 米（默认 4 米）。
    用平滑噪声实现——沿轨迹连续变化、有惯性，**不会出现随机跳点**（跳点在地图上就是毛刺，
    打卡类 App 的速度/抖动风控很容易识别）。
  - **速度浮动**：瞬时速度在设定值上下平滑波动，幅度 0~60%（默认 ±8%）。
  - **发送节奏抖动**（默认开）：真实手机 GPS 不是精确每秒一次，而是 0.85~1.15 秒抖动、
    偶发丢一次采样（约 2%）。间隔完全均匀是最容易被数据侧识别的特征之一。
  - **速度由位移推算**（默认开）：上报速度 = 实际位移 ÷ 实际时间间隔，与 iOS 从坐标序列
    推算 `CLLocation.speed` 的方式一致，因此**速度、位移、时间戳三者自洽**，
    不会出现"上报速度与轨迹推进矛盾"这种自曝式数据。
  - **注入粗差跳点**（默认关）：按概率插入多径/城市峡谷导致的坏点，
    用来测你自己 App 的 `horizontalAccuracy` 过滤与跳点剔除逻辑是否生效。
  - 所有开关与幅度都会持久化，下次启动沿用；播放中调整立即生效。

  技术实现：位置漂移用**多尺度值噪声**（慢漂 120m + 中尺度 30m + 快抖 15m 相关长度，
  接近真实 GPS 误差的幂律谱），幅值标定到设定半径并做上限裁剪（1.8 倍）；
  相邻上报点之间平滑过渡，不会出现随机跳点造成的毛刺。
- **路线概览**：总距离、按速度预计耗时、按倍速播放耗时、路径点数、途经点数、路线引擎（OSRM 真实路网 / 直线）
- **途经点列表**：拖拽排序、双击改坐标、删除、定位到该点
- **本地保存的路线**：保存 / 载入 / 删除（浏览器本地存储）
- **底图**：高德矢量（GCJ-02，带中文标注）/ 高德卫星 / 全球卫星(Esri) / OpenStreetMap
- 操作：「加载 OSRM 路线」「清空」「导出 GPX」「导入 GPX」「恢复真实定位」
- 瓦片缓存：显示缓存目录与占用，「清理瓦片缓存」

### 地图工具条
- **选择**：拖动地图、拖拽途经点、点击编辑
- **添加途经点**：在地图上连续点击加点（这是最常用的绘制方式）
- **折线绘制**：连续点击画折线，双击或 Esc 结束
- **撤销上一步**、**删除选中点**、**全览**

### 底部：播放条
- 播放 / 暂停 / 继续 / 停止
- 进度条（可拖动跳转，即 seek）
- 已用时间、剩余时间、序号
- 实时速度、当前坐标、倍速

### 右侧：运行日志
实时显示设备连接、隧道建立、每次定位下发的日志，便于排查问题。

## 4. 典型用法

**A. 沿真实道路跑一条轨迹**

1. 连接设备 → 「连接设备」（iOS 17+ 会自动建隧道，最长约 1 分钟）
2. 点「添加途经点」，在地图上点起点、中间点、终点（至少 2 个）
3. 点「加载 OSRM 路线」→ 生成真实路网折线（无网络时自动退化为直线）
4. 调「播放倍速」（例如 20x 可以在几秒内跑完 10 公里）
5. 点「播放」→ 手机定位会沿轨迹移动；地图上定位点与进度实时更新
6. 点「停止」→ 手机立刻恢复真实定位

**B. 单点定位（钉在某处不动）**

在「选择」工具下双击地图任意位置，或点途经点列表里的「定位到此处」。用完点「恢复真实定位」。

**C. 导入已有轨迹**

点「导入 GPX」选择 `.gpx` 文件 → 轨迹出现在地图上 → 播放。导出的 GPX 也能导入 Google Earth、Strava 等工具。

**D. 没有设备时预览效果**

```bash
./.venv/bin/python main.py --mock
```
界面、轨迹绘制、播放引擎、进度条全部可用，只是定位不会真正下发到手机（顶部会显示「当前为模拟模式」）。

## 6. 故障排查

| 现象 | 原因与处理 |
| --- | --- |
| 界面显示「本地服务未连接」 | 服务端没起来或端口被占。看终端是否有报错；换端口 `--port 8899` |
| 未检测到设备 | 数据线 + 解锁 + 点「信任」；iOS 26 的网络连接设备需要先在手机上信任 |
| 提示「需要开发者模式」 | 设置 → 隐私与安全性 → 开发者模式 → 打开并重启手机 |
| 连接设备报「隧道」相关错误 | ① 关闭爱思助手等同类工具（会抢 RSD 连接）；② 点「以管理员权限重建隧道」；③ 确认开发者镜像已挂载 |
| `developer` 命令失败 / 提示没有开发者镜像 | `./.venv/bin/python -m pymobiledevice3 mounter auto-mount --udid <UDID>` |
| 定位不生效（手机没动） | 确认「虚拟定位」显示"模拟中"；iOS 17+ 必须隧道正常；某些 App 使用独立的定位通道（见下方限制） |
| 地图一片空白 | 瓦片源被网络限制，换底图（高德卫星 / Esri）；**已浏览过的区域断网也能显示**（瓦片落在 `~/.ios-location-tiles`，上限 1GB，LRU 淘汰）。验证方式：`./.venv/bin/python tests/offline_browser.py` |
| 隧道建好后手机定位立刻恢复 | 有别的程序（爱思/i4Tools/Xcode）在抢同一条 RSD 连接，关掉它们 |

## 7. 技术说明（实现要点）

- **通信**：Python 标准库 `http.server` + 手写 WebSocket（RFC 6455），无第三方 Web 框架；设备侧用 `pymobiledevice3`。
- **虚拟定位**：DVT 服务 `com.apple.instruments.dtservicehub`（iOS 17+，走 RSD）或 `com.apple.instruments.remoteserver.DVTSecureSocketProxy`（iOS <17，走 usbmux），调用 `LocationSimulation.set(lat, lon)` / `clear()`。
  **连接必须长连接保持**——DVT 会话一断，模拟定位立即失效，这决定了播放引擎不能每发一个点就重连。
- **播放引擎**：按弧长积分推进；速度剖面按转弯角度生成（急弯自动减速）再做滑动平均，因此加减速自然。独立线程 + 单一在途请求，保证下发顺序严格不乱；默认 5Hz 下发（可配 1–20Hz）。
- **坐标**：内部与后端**一律 WGS84**；高德/腾讯瓦片是 GCJ-02，由前端在请求瓦片与落点时做转换，避免"地图上的点和实际定位差 500 米"。
- **瓦片**：服务端代理 + 磁盘缓存（默认 `~/.ios-location-tiles`，上限 1GB，LRU 淘汰）。会自动识别并丢弃服务商返回的"全透明空瓦片"。
- **路线**：优先 OSRM 真实路网（`router.project-osrm.org`），无网络时退化为直线并在地图上标注引擎类型。
- **接口契约**：见 [docs/PROTOCOL.md](docs/PROTOCOL.md)；设备侧取证记录见 [docs/DEVICE_NOTES.md](docs/DEVICE_NOTES.md)。

## 8. 已知限制

- **部分 App 不受影响**：使用独立定位通道的 App（例如部分地图 App 的"真实定位"、需要硬件级校验的场景）可能不会跟随模拟定位。系统级定位、微信/钉钉等常规 App 通常有效。
- **同一时间只能有一个工具占隧道**：iOS 17+ 设备只有一条 RSD 连接，爱思助手/Xcode 与本工具会互相挤掉。
- 首次挂载开发者镜像需要能访问 GitHub 与 Apple TSS 服务器；若网络受限，请在网络环境更好的机器上挂载或用 Xcode 挂载（镜像挂在手机上，与本工具无关）。
- 地图瓦片来自公开服务，仅供个人测试使用，请遵守相应服务条款。

## 10. 校园跑 / 打卡类 App 测试建议

这类 App 通常会在服务端做轨迹合理性校验，**固定点位、匀速直线、每点等距**是最容易被识别为模拟的特征。
本工具的「真实感模拟」针对这几点：

| 容易被识别的特征 | 本工具的处理 |
| --- | --- |
| 点位固定不动 | 开启**定位漂移**：沿轨迹缓慢游走，模拟 GPS 误差（建议 4~8 米，城市环境量级） |
| 速度完全恒定 | 开启**速度浮动**：瞬时速度上下波动（建议 ±8%~15%，接近真人配速波动） |
| 相邻点间距完全一致 | 漂移 + 浮动共同作用，使每次上报的间距自然起伏（实测间距波动平稳但不等距） |
| 轨迹是理想折线 | 用**添加途经点 + 加载 OSRM 路线**走真实路网，而不是手绘直线 |
| 配速不符合运动特征 | 出行模式选**步行（约 1.4 m/s）**或**骑行**；也可在 `config.json` 调整 `mode_defaults` |

推荐参数（校园跑场景）：
- 出行模式：**步行** 或 **骑行**
- 播放倍速：**1.0x**（按真实时间跑，倍速过高会导致配速不合理）
- 定位漂移：**4~8 米**
- 速度浮动：**±8%~15%**
- 循环播放：按需（绕操场多圈时有用）

**注意**：请仅用于自己有权测试的 App 与场景（例如你参与开发/测试的产品），
不要用于伪造他人行程、规避考勤等用途——详见下一节。
